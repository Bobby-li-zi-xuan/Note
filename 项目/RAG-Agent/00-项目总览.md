# 00 · 项目总览

## 一、项目定位

RAG-Agent 是一个**面向知识检索与工具增强的多轮 Agent 对话系统**。它不只是"调大模型 API 回答问题"，而是实现了完整的 **Think → Execute → Cache → Push** 闭环：

- LLM 负责决策（要不要调工具、调哪个工具）
- 程序负责控制（工具执行、失败恢复、记忆管理、消息推送）
- 缓存体系保证重启后会话可恢复
- SSE 实时推送让前端感知 Agent 每一步在做什么

一句话概括：**把"调用大模型"这件事工程化成了可恢复、可观测、可扩展的 Agent 系统。**

## 四、核心数据流

用户发一条消息的完整路径：

```
1. POST /api/chat-sessions/{id}/messages  ← 用户消息入库
2. ChatEventListener 触发 Agent 执行
3. RAGAgentFactory.create(agentId, sessionId)
   ├─ 从 DB 加载 Agent 配置（模型、工具白名单、知识库列表）
   ├─ 从冷存储恢复最近 N 条历史消息
   ├─ 从 L2 缓存恢复结构化记忆快照
   └─ 组装 ToolCallback[]、ChatMemoryManager、MessagePublisher
4. AgentCore.run()  ← 主循环
   └─ for step in 1..maxSteps:
        ├─ think()  → LLM 决策 → {工具调用/直接回复}
        ├─ execute() → 执行工具 → 写回记忆 → checkpoint
        └─ 流式/批量推送消息到前端
5. finally → flushSessionCache()
   ├─ checkpointSessionCache()  ← 增量摘要写入 L2
   └─ asyncMemoryWriteService.submit()  ← 异步刷盘到 L3
```

## 六、面试问答

### Q: 一句话介绍这个项目？

> 我做的这个项目是一个带工具调用和知识检索的 Agent 对话系统。核心是让 LLM 不只是生成文本，而是能主动调用工具——查知识库、查数据库、发邮件这些。同时在工程上做了三层缓存保证会话可恢复，做了工具失败恢复防止单次调用失败导致整个对话崩掉，还通过 SSE 让前端能实时看到 Agent 每一步在做什么。

### Q: 和其他 LLM 对话项目有什么区别？

> 最大的区别在于我把 Spring AI 的自动化工具执行关掉了，改成自己控制 think 和 execute 两个阶段。这样做的好处是能在 LLM 决策和工具执行之间插入业务逻辑——持久化消息、推送状态、失败重试。还有，我做了个三层记忆缓存体系：L1 存当前对话窗口、L2 存结构化摘要快照、L3 持久化到数据库。会话关闭后再打开，能从冷存储恢复上下文，不是每次从头开始。

### Q: 你的角色是什么？做了什么决策？

> 这个项目是我独立设计开发的。比较大的技术决策有两个：一是选择自己编排 think/execute 而不是用 Spring AI 自动执行工具；二是不引入 Redis 或 Milvus，直接在 PostgreSQL 上用 pgvector 做向量检索，降低运维复杂度。工具失败恢复的三层机制也是我从零设计的——先是代码层的快速重试，然后是策略重试，最后才是让 LLM 介入决策，每层都有预算上限，不会死循环。

### Q: 你在这个项目中遇到的最大技术挑战是什么？

> 有两个。第一个是工具调用失败恢复。不是简单地 try-catch，而是设计了"快速重试 → 策略重试 → LLM 决策"这样一套有限状态机，每层都有预算控制。还让 LLM 能根据失败上下文动态调整重试策略——比如网络抖动时多等一会儿，参数错误时直接降级。第二个是记忆缓存的一致性。我在 L2 里做了增量摘要和合并淘汰——新摘要和老摘要按类型分组、按相似度去重、再按置信度和版本号排序保留 top-N。这比简单的"全量替换"更精细。

### Q: 项目还有哪些可以改进的地方？

> 目前最大的改进空间是摘要质量。现在的增量摘要是用规则做的——截取最近 N 条消息按模板拼装，没有用 LLM 来做。如果面试官问到这一点，我会说：用规则的优势是零成本、低延迟，但语义质量不如 LLM 摘要。下一步可以做一个混合策略——大部分情况下用规则摘要，当对话主题发生重大变化时触发一次 LLM 摘要，相当于在成本和效果之间找平衡。

> 还有一个是目前 pgvector 的检索用的 L2 距离，对高维向量来说余弦距离更合适。我在配置里已经设了 maxDistance 转换，但更理想的做法是直接换距离度量或者规范化向量后用内积。
